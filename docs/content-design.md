# 分野共通の教材設計

## 役割と読み順

視覚的・対話的な教材で、既知の具体的な状況や操作を、新しい関係の理解へつなぐ制作原則を定める。
科目、フレームワーク、保存先、実行コマンドを必須前提にしない。
[文章と図の規範](writing-guidelines.md)で表現を整え、[教材設計テンプレート](templates/lesson.md)で教材ごとの設計を記録する。
別プロジェクトでは対象読者、分野の検証基準、表示への結合、技術とコマンドを、そのプロジェクトの設定文書で定める。
このリポジトリの設定は[science-studyの教材方針](project-design.md)、実装は[アーキテクチャ](architecture.md)、題材は[概念の地図](learning-map.md)に分ける。
設定文書への参照はこのプロジェクトの入口であり、共通原則を持ち出す際の依存ではない。

## 基本の学習順序

**既知の具体的な状況・操作 → 関係を見つける → 表現・抽象化 → 別の状況に適用**を基本とする。
身近な物の名を導入に添えるだけで終えず、同じ対象・比較基準を保って新しい概念へ渡す。
本人が経験済みと決めつけず、場面自体を図と操作で示す。
物理実験だけを要求しない。個数、並び、図形、生活上の数量の比較も具体的な入口になる。
目に見えない対象は、見える印・軸・グラフが何を表し何を省くかを明示する。

| 入口 | 見つける関係 | 表現・抽象化 | 別の状況への接続 |
| --- | --- | --- | --- |
| 小物を1列3個ずつ並べ、同じ並びの列を1列ずつ追加する | 1列増えると3個増える | 列数と個数の対応から乗算へ | 座席の列。整数の例だけでは実数の乗算を説明しきらない |
| 方眼の長方形を切り、同じ部分を並べ直す | 覆う単位正方形の個数は変わらない | 個数と辺の長さを対応させ面積へ | 部屋の広さ。数個の例を全図形の証明とはしない |
| 同じ単価で繰り返す支払いを表に置く | 一回分を足すと合計が増える | 表の差、点、式を同じ量の表現としてつなぐ | 別の料金。固定費・丸めなど異なる条件を確認する |

操作から見えた関係、モデル内で計算した結果、定義から導いた結論、実測の適合は分けて説明する。
科学では単位・理想化・適用範囲・実測との対応、数学では定義・仮定・定義域・証明と例の範囲を検証する。
一つの分野の正しさを、用語だけ置き換えて他分野へ適用しない。

## 理解のゴールを現実世界の行為に結び付ける

入口に「今回理解すること」を置き、次の四点を示す。
ここでいう行為には、物を見ることに加え、数える・並べる・分ける・図や数量を比較する操作を含む。
抽象対象を生活の物へ無理に置き換えず、操作できる表現との対応から始めてもよい。

| 必ず示すもの | 書く内容 |
| --- | --- |
| 身近な行為 | 何をする場面か。経験済みと決めつけず、見る対象や操作を示す |
| そこで起きていること | 行為の中の対象、変化、変わらない比較基準 |
| 理解する関係 | 何の違いが何と結び付くか。因果だけでなく対応・同値・構造も扱える |
| 扱う範囲 | この表現・モデル・定義で何を説明でき、何を扱わないか |

専門用語や公式の一覧をゴールにせず、具体的な場面の何が分かるかを書く。
中心の問いはゴールを掘り下げるために置き、答えと理由を同じ図でたどれるようにする。
最初の画面では行為と結び付いた理解する関係を示し、対象・変化・範囲を近くに置く。
教材への案内も同じゴールを参照し、未実装のテーマは候補として区別する。

## 身近な感覚から概念へ橋を渡す

直接の現象、同じ対象の表現、別の物の比喩を区別する。
毎文に無理な比喩を付けず、新しい概念や段落ごとに指せる対象、比較、基準を確保する。
同じ対象から図・グラフへ移す場合も橋渡しに含める。

1. **場面と関係を選ぶ。** 見たり操作したりできる状況から、順序・割合・積み重ね・向き・対応など中心の問いに必要な関係を選ぶ。
2. **対応を図で渡す。** 同じ目印・配置・量・比較基準を保ち、置き換える対象と保つ関係を近くの言葉で示す。色だけで対応を読ませない。
3. **対象を見てから名前を付ける。** 対象と振る舞いを図で見てから必要最小限の語を導入する。定義に未説明語があれば具体像へ戻る。
4. **対応の境界を示す。** 比喩で引き継がない性質や表現の省略を、違いが効く場面で示す。模式図の動きやいくつかの例を証明の代わりにしない。
5. **元の状況と別の状況へ戻る。** 同じ対象を指して何が説明できたかを示し、別の例で同じ関係と変わる条件を比べる。

「同じ」「増える」「垂直」「その方向」は、対象・量・基準を特定する。
物の移動、値の変化、変化の伝わり方を区別する。
中心の説明に不要な前提は任意の詳細へ分けるが、現在の図を読むための対象・定義・比較基準・比喩の限界は近くに残す。
扱う深さを決め、前提を際限なく増やさない。
「式の形が生まれる理由」「モデル内の仕組み」「より根本の理論」は分けて説明する。

## 未説明の言葉を積み重ねない

全体像を先に示すことは、専門用語の一覧を先に見せることではない。
各新概念について、何を指すか、変化と不変、中心の問いとの関係、混同しやすい比較、操作、表現の省略を記録する。
図で見た対象と動き→名前→同じ例と異なる例の比較→概念同士の接続を基本とする。
「図のどこに指せるか」を、本文を書く前と完成後に確認する。

## 説明と操作を一緒に設計する

### 作成・改善の順序

1. 行為・状況、理解する関係と範囲、中心の問いを定める。
2. 問いを図で指せる中間の関係へ分ける。新しい対象へ移っても目印と比較基準を保つ。
3. [テンプレート](templates/lesson.md)の4つの表へ、ゴール・橋渡し・命名・場面を記す。場面の配置と状態も決める。
4. 何を変え何を保つ操作かを定め、現在の図から説明を書く。条件・数値・文章を同じ結果に対応させる。
5. 任意の詳細を閉じても中心の問いの理由が分かる構成にし、入口と別の具体例へ戻る。
6. モデル・定義・資料を照合し、実画面を一周する。修正した配置・状態・説明を設計記録へ戻す。

表は制作者の記録であり、学習者へのノート・メモ・説明課題ではない。
予想の入力、正誤・採点、理解度チェック、回答提出、完了判定、学習履歴を設けず、図と操作を自由にたどれるようにする。
順序は理解を支える案内として示し、回答で閲覧をロックしない。
本人の理解や達成を自動的に評価・記録しない。設計・根拠・開発検証の記録は保持する。

### 操作の役割

| 役割 | 変えるもの | 設計の判断 |
| --- | --- | --- |
| 場面を選ぶ | 対象や説明の段階 | 現在の場面を示し、直接選べる。静止場面も用意する |
| 見方を選ぶ | 重ねる線・寄与・視点 | 排他的な選択と独立した表示のオン・オフを区別する |
| 条件を変える | モデルの量、並び、対象 | 単位・基準・範囲を示す。比較条件は隣に置く |
| 時間を選ぶ | 説明時刻または対象の時間 | 停止・初期化・任意の時刻を図の近くに置き、時間の意味を示す |
| 詳細を開く | 補足の表示 | 現在の図を読むための条件と限界を隠さない |

採用しているUIの標準部品とテーマを使い、表現ごとに操作の外観を作り直さない。
部品の種類だけを理由に汎用エンジンや依存関係を増やさない。
具体的な部品名はプロジェクトの実装文書で指定する。

### 配置と状態の設計

広い画面では対応する図・説明・操作を隣に置く。
狭い画面では同じ場面の中で読み進められる順序にまとめ、図の比率、ラベル、折り返し、操作の幅を確認する。
本文は読みやすい中立色と行幅を保ち、強調色を説明の大きな面へ無条件に広げない。
操作を減らす場合も比較対象や成立条件は残す。

- 同じ場面を選び直したら、条件と時刻を保持する。先頭へ戻す操作は別に示す。
- 見方を変えるときは同じ対象・条件・時刻で比べる。説明の都合で特定の状態へ移す場合は理由と移動先を記す。
- 別の場面や条件への移動では、保持する比較基準と停止・初期化する状態を決める。静止した解析式と再生中の運動を区別する。
- 表示だけの変更でモデルの条件を変えず、図・数値・観察文を同期させる。
- 再生は手動で開始し、時刻指定で停止する。動きを減らす設定、非表示、離脱の停止・解除を設計する。

## 認知への配慮と表現

認知への配慮は説明の順序、一度に見せる量、注目箇所、図と言葉、操作に反映する。
本人の認知特性や習得度を推定して分類しない。
用語集や文章の言い換えだけで終えず、一場面の新しい関係を絞る。
対応する図・グラフ・式を同じ量の別の見方としてつなぎ、名前・線種も使う。
同じ尺度で変化と不変を比べ、縮尺が変わるなら近くに明記する。
自動再生せず、静止図・値・短い説明でも関係を追えるようにする。

| 見たい関係 | 表現の候補 |
| --- | --- |
| 時間に沿う変化 | 停止できる動き、時刻の操作、過去の位置の印 |
| 状態・変化率・積み重ね | 対応する図とグラフ、面積や傾き |
| 個数・並び・同じ構造 | 動かせる印、対応線、同じ要素の並べ替え |
| 奥行き・断面・向き | 視点と断面の操作。必要なら3D |
| 因果・対応・条件に依存する関係 | 全体図と段階表示、一つずつ変える条件、比較対象 |

3Dやアニメーションを使うこと自体を目的にしない。
説明の演出、解析式、数値シミュレーション、実測データを混同しない。
前提概念を先に見ること、自分のペースで区切ること、図と説明を近くに置くこと、注目箇所を示すことは、末尾の研究から参考にした設計判断である。
研究を、この教材の学習効果や特定の本人への最適化の証拠にはしない。

## 検証を分ける

| 検証 | 確認する内容 | それだけでは言えないこと |
| --- | --- | --- |
| 分野の妥当性 | 定義・式・仮定・適用範囲・資料。科学なら単位・理想化・実測との対応、数学なら定義域・証明・反例 | コードが正しく表示すること |
| モデルと構造 | 既知の解、対称性、不変量、境界、変化しない条件。必須の設計項目・空欄 | 表の完成だけで説明が分かりやすいこと |
| 実装と実画面 | 図・数値・文章の同期、状態・配置・操作・読み取り | 現実への適合や学習効果 |
| 学習効果 | 学習者による検証を別途行った場合だけ、その方法と範囲 | 利用者一人の評価から全教材・全学習者への一般化 |

構造検査は項目の欠落を検出するために使い、表を埋めることだけで完了しない。
実装を写した期待値でモデルを検証せず、分野上の根拠から期待を作る。

### 実画面で確認すること

1. 名前の前に具体像があり、中間の関係を図で指せるか。比喩の対応と限界、入口への戻り方を照合する。
2. 場面へ直接移り、重ね合わせ・条件・時間を一つずつ変更する。同じ選択、前後移動、再生・停止・初期化を記録した状態と照合する。
3. 代表条件と境界、変化しない条件、比較量が等しい条件を確認する。入力がある場合は小数や末尾の0も含め、図・値・文の同期を確認する。
4. 広い画面と狭い画面、キーボード、動きを減らす設定で、図と説明を探し直さず読めるか。詳細を閉じても中心の理由がたどれるか。
5. プロジェクトの検証コマンドの結果、実ブラウザの環境・幅・操作、未確認事項を報告する。未確認を合格扱いしない。

## 追加・変更時のレビュー

先に分野の定義・前提・資料と説明の範囲をレビューし、次に対象→比較→説明図→命名の足場を実画面で指す。
語彙の前提、比較基準、中間段階、回収していない問い、必須課題の混入を確認する。
図・文・式・条件と4つの設計表をそろえ、具体的な不備を直したら関連する検証を再実行する。
新しい根拠のある不備がなくなったら、好みだけの修正を繰り返さず、検証範囲と残る限界を示す。
