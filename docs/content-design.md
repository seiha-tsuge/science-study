# 教材の設計契約

## 目的

世界の解像度を上げ、複雑な現象を生む関係について「なぜそうなるのか」を理解する支えを作る。
計算結果、正誤判定、課題の完了をゴールにしない。
予想の入力、自分の言葉で説明する課題、理解度チェック、採点は設けない。

「なぜ」は深さを持つ。
関係から式の形が生まれる理由、現象を生むモデル上の仕組み、より根本の理論を区別する。
例えば等加速度から二乗が現れる理由を説明しても、力の発生まで説明したことにはならない。
屈折の波面の作図は速さと向きの関係を支えるが、物質中の速さが決まる電磁的な詳細までは扱わない。
各教材で扱う深さを示し、その先の見方につなぐ。

## 利用者の要望として継続して適用すること

この文書は、利用者から繰り返し受けた次の要望を、今後の新規作成・修正でも適用するために残す。
光学だけの対応や、今回の画面改修の記録に限定しない。
ホーム・分野ページ・すべての教材の設計要件とする。

- 求めるものは、結果や公式を覚えることより、世界の見え方を細かくし、「なぜそうなるか」という抽象的な関係を理解する支え。
- 「波」「位相」「波面」を未説明のまま使うような、前提知識への依存が大きい説明を避ける。定義の中に別の未説明語を重ねても解決にはならない。
- 全体が何を扱うかを身近な言葉で示し、その全体を構成する対象と変化を図で見てから、細部の概念へ進める。
- 概念理解は身近な感覚から始め、知っている場面の関係を新しい対象へ対応させる。たとえやメタファーを使う場合も、関係を渡す図と操作、その対応の限界まで設計する。
- 操作部品の配色・形状はMantineの標準と共通テーマに合わせる。UXの改善は説明の順序、図と言葉の対応、条件変更の分かりやすさに反映し、教材ごとの装飾や独自のボタン外観を増やさない。
- 認知への配慮を、説明の順序・一度に見せる量・注目箇所・図と言葉の対応・操作の設計に反映する。文章の言い換えや用語集の追加だけで終えない。
- アニメーション・SVG・3D・場面や条件を変えるボタンを、現象や関係の具体像を作るために使う。表現は理解したい関係に合わせて選ぶ。
- 予想、理解度チェック、自分の言葉で説明する課題は要求しない。観察や操作を自由に行えるようにする。

作業を始めるときはこの文書を読み、終了前には末尾のレビュー項目に沿って成果を確認する。
新しい概念の導入が必要になったら、利用者から再び「その言葉は何か」「イメージがない」と指摘されるのを待たず、説明に必要な前提と図を作る。
本方針を変更する場合は、利用者の明示的な要望を根拠にし、AGENTS.md・README.md・この文書をそろえて更新する。

## 文章と図の規範を運用する

文章、図、操作の具体的な書き方は[科学教材の文章と図の規範](writing-guidelines.md)に定める。
利用者提供の二つの文章規範から、対象を見てから命名すること、段落ごとの論理、観察と説明の緩急、根拠と不確実性の保持を取り入れる。
科学的な正確さと必要な橋渡しを、文章の短さや演出より優先する。
緩急は図や操作にも適用し、答えの出し惜しみや架空の思い込みでは作らない。

新規教材では[教材設計テンプレート](templates/lesson.md)から `lesson.md` を作る。
既存教材でも、関係や説明を変えたら「身近な感覚から概念への橋渡し」「概念の導入」「観察と説明の流れ」を更新する。
橋渡しの表には身近な場面、そこで見える関係、新しい対象、図と操作で保つ対応、対応しない点、元の現象への戻り方を記す。
概念の表には名前の前に見るもの、図の対象、混同を避ける比較を記す。
場面の表には注目する対象、観察と操作、その場面で分かる関係、図・説明・操作の配置、切り替え時の状態を記す。
問いがどこで説明され、入口の現象へどう戻るかも残す。

`pnpm test` の `lesson-design.test.ts` は、`LessonPage.tsx` のある教材ディレクトリを自動で探索する。
`lesson.md` と三つの設計表の欠落、空欄、テンプレートの未記入を検出する。配置と状態の設計も検査対象に含める。
既存の教材構成テストと合わせて、新規教材も同じ設計手順で扱う。
自動検査が通ることと、説明が正確で分かりやすいことは区別し、後者は本文と図を見てレビューする。

## 全ページの構成

ホームは分野の位置づけと概念のつながりを、分野ページは全体の関係と各教材の位置づけを示す。
教材ページでは次の順序を共通の `Lesson` が組み立てる。
どの節も入力なしで開け、順番は強制しない。

| 内容 | 役割 | 実装 |
| --- | --- | --- |
| 全体像と中心の「なぜ」 | 細部が何の一部かを先に示す | meta の startingPoint・question・overview・relationships |
| 仕組みの可視化 | 概念間の関係や、現象が生まれる過程を見える形にする | 必須の mechanism |
| 条件を変える | 一つの変化と、その影響を対応させる | observation・simulation |
| 式と前提 | 図と式・単位・成立条件をつなぐ | 任意で開く explanation・常に見える sources |
| ほかの見方への接続 | 日常や次の概念へ視点を広げる | connection・next |

`LessonContent` は身近な入口・全体像・関係・接続を型で必須にし、Lesson は仕組みの図を必須の引数として受け取る。
`Lesson.test.tsx` は全教材の構成と、操作前の回答を求めるUIが混入していないことを確認する。
型やテストだけで説明の質は判定できない。
追加時のレビューで中心の「なぜ」と図の対応を確認する。

## 説明と操作を一緒に設計する

光の反射・屈折の改善について、利用者はUXと内容の説明がよくなったと評価し、その進め方を仕組みにするよう求めた。
ここで採用した、因果を図で追う構成と、操作を役割で分ける設計を、教材の新規作成・改善に継続して使う。
場面数や見た目は扱う関係に合わせて選ぶ。

### 作成・改善の順序

1. **問いを関係に分ける。** 中心の「なぜ」に答えるために、何の変化が、どの対象の変化につながるかを書く。光学なら「片側が先に境目へ届く → 同じ時間に進む距離が違う → 列が傾く → 列に90°の光の向きが変わる」と分ける。途中で必要になる概念とモデルの条件も確認する。
2. **各関係を図で指せるようにする。** 各場面で見る対象、固定した目印、変える量を決める。身近な図から新しい対象へ移るときも対応する目印を保つ。三つの設計表をここで書き、因果の間に図のない飛躍がないか確かめる。
3. **図を変える操作を決める。** 場面、重ね合わせ、条件、時間を分け、それぞれ何を変え、何を保つかを記録する。図を読むのに必要な操作と説明は同じ表示領域に置く。式の導出や追加の理論は任意で開く。
4. **現在の図から説明を書く。** 最初に見る対象を指し、観察できる違い、理由、必要な名前を順に示す。条件を変えた場合の文章と数値も同じモデルの結果に対応させる。最後に入口と同じ対象へ戻り、問いへの答えと扱える範囲を示す。
5. **画面で一周し、設計記録と照合する。** 全体像から直接移動し、条件・見方・時間を変え、詳細を開閉する。幅390pxを目安に狭い画面も確認し、修正した配置・状態・説明を設計表へ戻す。

### 操作の役割と標準部品

同じ列に並べる前に、操作が何を変えるかを区別する。
少数の相互排他的な選択には、選択中の対象が分かる標準部品を使う。

| 役割 | 変えるもの | 部品と配置の判断 |
| --- | --- | --- |
| 場面を選ぶ | 見る対象や説明の場面 | 独立した場面は `Tabs`、特定の時刻の静止場面はラベル付きの `Button`。現在の場面を示し、直接選べるようにする |
| 図の見方を選ぶ | 重ねる線・寄与・視点 | 一つを選ぶ `SegmentedControl`、独立した表示のオン・オフは `Switch`。「図に重ねるもの」など対象を指すラベルを付ける |
| 条件を変える | モデルに渡す量や物質 | `Slider`、必要なら同じ状態を共有する `NumberInput`、物質は `NativeSelect`。対になる条件は並べ、単位・基準・範囲を示す |
| 時間を選ぶ・再生する | 説明の時刻または物理時刻 | 静止場面の `Button`、時刻の `Slider`、再生・停止・初期化の `Button` を図の近くにまとめる。どちらの時刻かを明示する |
| 詳細を開く | 補足の表示 | `Accordion` や共通Lessonの開閉。現在の図を読むための対象・基準・たとえの限界は図の近くに残す |

部品の配色・形状・選択表示はMantineと共通テーマに任せる。
独自CSSは図と説明の配置、SVG・canvas、式の表示に使う。
部品の種類だけを理由に、新しい依存関係や汎用の場面エンジンを追加しない。

### 配置と状態の設計

広い画面では図と対応する操作・説明を隣り合わせに置くことを基本とする。
狭い画面では同じ場面の中にまとめ、読むために必要な説明、操作、図、関係の説明を近い位置でたどれる順に並べる。
図の縦横比、ラベルの折り返し、操作の横幅を確認する。
操作を減らす場合も、比較対象や成立条件の説明は残す。

各場面の「切り替え時の状態」に、次を具体的に書く。

- 同じ場面のタブを選び直したときは、条件と時刻を保持する。先頭へ戻す操作は別に示す。
- 見方を変えるときは同じ対象・条件・時刻で比較することを優先する。説明に必要な到達状態へ移す場合は、選ぶ時刻と理由を記す。
- 別の場面や条件へ移るとき、停止・初期化するものと保持する比較基準を決める。時刻を保てる静止した解析式の図と、条件変更で0秒へ戻す運動を区別する。
- 表示切り替えでモデルの条件を変えない。表示中の条件、図、数値、観察文を対応させる。
- 再生は手動で開始し、時刻指定では停止する。動きを減らす設定、非表示タブ、離脱時の停止・解除を確認する。

### 実画面で確認すること

学習者への課題ではなく、制作者が行うレビューである。

1. 図の対象を指しながら、名前の前に具体像があり、原因から結果まで中間の関係を追えるか確認する。たとえの対応と限界、入口の現象への戻り方も照合する。
2. すべての場面へ直接移り、図の重ね合わせ、条件、時間を一つずつ変更する。同じ選択の再操作、前後の移動、再生・停止・初期化も記録した状態と照合する。
3. 代表条件に加え、境界値、変化が起こらない条件、比較する量が等しい条件を確認する。数値入力がある場合は小数や末尾の0も含め、図・数値・文章が同期するか確認する。
4. 広い画面と狭い画面で、対応する操作と図を探し直さずに読めるか確認する。キーボードで選択と現在の状態を識別でき、詳細を閉じていても中心の理由がたどれるか確認する。
5. lint・型検査・テスト・ビルドの結果と、実画面で確認した幅・操作・未確認事項を作業報告に残す。

設計表の自動検査は記録の欠落を検出する。
因果の説明、図と文章の意味、操作中の分かりやすさは、ソースと実画面のレビューで確認する。
利用者の今回の評価は設計を継続する根拠として扱い、一般的な学習効果が実証されたとは扱わない。

## 身近な感覚から概念へ橋を渡す

新しい概念の中心にある関係を、身近な場面で見える関係へ対応させる。
「身近な場面 → そこで見える関係 → 新しい対象への対応 → 名前 → 元の現象」の流れを設計する。
同じ現象を動きからグラフへ移す場合も橋渡しに含める。
別の物のたとえがかえって混同を増やす場合は、直接の観察と表現の対応を使う。

1. **場面と関係を選ぶ。** 歩く、物を動かす、量を足すなど、図で示せる場面から始める。経験済みと決めつけず、その場面自体も見せる。外見の似た物より、中心の「なぜ」に必要な順序・割合・積み重ね・向きの関係を選ぶ。
2. **対応を図で渡す。** 身近な場面と新しい対象で、対応する目印・配置・名前・操作を保つ。切り替えるときは、何を置き換え、どの関係を保つかを近くの言葉で示す。色だけで対応を読ませない。
3. **対象を見てから名付ける。** 新しい対象でも関係を追える状態で用語を導入する。たとえの理解に必要な専門語を先に積み重ねない。中心の説明に不要な前提は任意の詳細へ分ける。
4. **対応の境界を示す。** 対応しない動きや性質を、その違いが効く場面で明示する。模式図の動きから科学の法則を証明したことにせず、モデルの式・条件・資料と照合する。
5. **元の現象へ戻る。** 同じ図の対象を保ち、入口の現象がどの関係で説明できるかを示す。条件の比較は観察のために用意し、理解度チェックにはしない。

例えば光学では「一方が先に遅い場所へ入り、同じ時間に進む距離に差がつくと列が傾く」を人の列で見せ、A側・B側を保って波の目印へ移す。
人の歩く向きは光の向きへ対応させず、光の向きは波の目印に90°の矢印として別に示す。
最後は同じストローの点へ戻り、曲がって目に届く光と、その道筋を逆へ延ばした見える位置をつなぐ。
力学では同じ物体・同じ時刻の位置を道とグラフで対応させられるため、別のたとえ話を必須にしない。

橋渡しの設計表は、導入の小話を追加したという記録ではない。
虫めがねや鏡などの日常の現象名を挙げ、すぐ専門の光線図へ移るだけでは、橋渡しを用意したとしない。
既知の感覚で追える関係が図にあり、その対象・変化・比較の基準を新しい概念の図へ渡せるかを確認する。
レビューでは表の各対応を実際の図で指し、条件を変えたときにも関係が保たれるか、対応しない性質を持ち込んでいないかを確認する。
利用者が今回の教材を分かりやすいと評価したことは、この方針を採用する根拠として残す。
すべての教材や学習者で効果が実証されたという意味には広げない。

## 未説明の言葉を積み重ねない

全体像を先に示すことは、専門用語を一覧にすることではない。
「同じ位相の場所を結んだ波面は進行方向に垂直」と一文で言う前に、位相・結ぶ・面・進む方向をそれぞれ指せる図を用意する。

1. 身近な場面と、そこから見たい現象を示す。本人が経験済みだと決めつけない。
2. 図で対象と動きを見せる。「物体の移動」「値の変化」「変化の伝播」を区別する。
3. 見た対象や関係に名前を付ける。定義の中に新しい語をさらに増やさない。
4. 同じ例と異なる例を操作で並べ、概念の境界を示す。
5. 導入した概念をつなぐ。式・厳密な前提は必要なときに開く。

共通の `startingPoint` は、具体的な場面と図で見たい対象を型で必須にする。
この項目だけで分かりやすさは保証できない。
レビューでは次の語を使う時点で、その語を図のどこに指せるかを確認する。
「これ」「その方向」「垂直」などの指示語は、対象と基準の両方を示す。
類推から実際の現象へ移るときは、同じ点と異なる点を明示する。
ひもでは物質が上下するが、光の電場のグラフの高さは物体の位置ではない。

### 説明を書く前に確認すること

各教材の `lesson.md` に、中心の関係を追うために必要な新しい概念と、それを支える具体像を残す。
説明に必要な前提をたどり、まだ導入していない概念があれば先に対象と振る舞いを見せる。
前提を際限なく増やすのではなく、この教材で扱う深さを定め、先の理論は接続先と扱わない範囲を示す。

| 概念ごとに確認すること | 教材に残す内容 |
| --- | --- |
| 何を指す言葉か | 図の対象・場所・量との対応 |
| 何が変わり、何が変わらないか | 動き・固定した目印・軸・比較対象 |
| どの関係を理解するために必要か | 全体像と中心の「なぜ」へのつながり |
| 初めて見る人がどこで混同しうるか | 同じ例と異なる例、基準となる面や方向 |
| 何を操作すると関係が見えるか | 場面・時間・視点・条件の操作と短い説明 |
| 図は現実の何を表し、何を省くか | 類推・模式図・モデルの前提と限界 |

これは制作者の設計・レビュー用で、学習者に回答させる項目ではない。

### 今回の指摘を、ほかの教材にも使える判断基準として残す

| つまずく説明 | 必要な具体像・区別 |
| --- | --- |
| 「光線は波が進む方向を表す線」 | まず波では何が変わり、何が伝わるかを見る。光では何の変化を表しているかと、波として扱う観察の手がかりを示す。 |
| 「同じ位相」 | 繰り返しのどの段階かを見る。同じ値でも、その後に上がる場合と下がる場合を比較する。 |
| 「同じ位相の場所を結ぶ」 | 条件に合う場所を図で選び、連続した集合として示す。「位相がない場所」や、実在する糸でつながった場所と混同させない。 |
| 「波面」 | 同じ進み具合の場所が空間で面になる様子と、その断面を対応させる。実在する物質の表面とは区別する。 |
| 「その方向に垂直」 | 対象となる線・面・矢印を名前で指す。波面に垂直な光の向きと、水面に垂直な基準線を別々に示す。 |
| 「斜めの波面が物質の境界に入る」 | 空気と水が接する水面と、そこへ到達する波面を描き分ける。一部が先に届く様子から、向きの変化をたどる。 |

ほかの分野でも、「何を指すか」「何が変わるか」「何と何の関係か」を図で追えるかという同じ観点で確認する。

### 光学での適用例

`RefractionJourney` はストロー → 人の列 → 波の目印と光の向き → 同じストローの四場面を切り替える。
人の列は到着順・同じ時間に進む距離の違い・列の傾きの関係を示す。
波の図への切り替えではA側・B側の配置を保ち、列に90°の光の向きを別の段階で加える。
人の歩く向きを光へ対応させず、たとえから科学の性質を導いたことにしない。
入口と着地点の同じストローの図に実際の光路と逆向きの延長を重ね、実際の点と見える点を対応させる。
電場・干渉・位相を含む `WavePrimer` の六場面は任意の詳細とし、本筋の前提として要求しない。
一度に一つの場面を表示し、名前と短い説明を同じ図の近くに置く。
同じ高さでも変化の向きが異なる例を、同じ位相の例と並べる。
波面は上からの断面と奥行きのある面を同じ例で切り替え、「光線の向きに90°」と「水面に90°の法線」を区別する。
進む順番、予想、正答、説明の提出は要求しない。
幾何学の作図は任意で開く。

前提概念の名前と振る舞いを先に見ること（pretraining）、自分のペースで区切って見ること（segmenting）、
図と説明を近くに置くこと（spatial contiguity）、注目箇所を示すこと（signaling）は、下記のMayer・Morenoの研究から参考にした設計判断。
具体例から名前を付け、例と異なる例を比較することは、この教材で採用する構成方針。
これらを本人の認知負荷の測定や、理解が改善したという評価と混同しない。

## 認知への配慮をUIに落とす

人が一度に扱える情報には限りがある、という設計上の出発点から、次を採用する。
本人の認知特性や習得度を推定して分類するものではない。

- 全体の関係を先に示す。新しい語は、図の中で何に対応するかも示す。
- 一度に強調する関係を絞る。長い演出は場面に区切り、短い説明を対応する図の近くに置く。
- 変化と不変を比べる。比較図では共通の軸を使い、縮尺が変わる場合はそのことを示す。
- 図・グラフ・式は同じ量を表す別の見方としてつなぐ。色だけでなく名前・線種も使う。
- 操作は関係を見るために使う。選択肢の正誤やボタンを押した回数を理解度とみなさない。
- 自動再生を避け、停止・巻き戻し・場面選択を用意する。静止画や数値・文章からも関係を読み取れるようにする。
- 詳細な式や限界は任意で開ける。資料へのリンクは詳細を閉じていても参照できる。
- 類推は何が対応するかと、どこまで成り立つかを示す。美しい演出や日常のたとえを、物理的な証明の代わりにしない。

段階に分けること、対応する図と言葉を近くに置くこと、無関係な情報を減らすことは、Mayer・Morenoのマルチメディア学習研究を参考にした設計判断。
その研究を本教材の学習効果や、特定の本人への最適化の証拠として扱わない。

## 表現の選び方

| 理解したい関係 | 表現の候補 |
| --- | --- |
| 時間に沿う変化 | 停止できるアニメーション、時刻の操作、過去の位置の印 |
| 状態・変化率・積み重ね | 対応する図とグラフ、面積や傾きの強調 |
| 空間の奥行き・断面・向き | 視点を操作できる3Dや断面図 |
| 因果の順序・構造 | 全体図と段階表示、関係を選ぶボタン |
| 前提に依存する関係 | 一つずつ変えられる条件、比較対象、限界の表示 |

力学は2Dで関係を示し、光学の波面はSVGの奥行きのある投影図も使う。
3Dも禁止しないが、奥行きが理解に役立つ題材になってから導入する。
説明の演出、解析式の評価、数値シミュレーション、実測データを混同しない。

## 追加・変更時のレビュー

1. 中心の「なぜ」と、教材で扱う説明の深さを定める。
2. 文章と図の規範を読み、未説明の用語と必要な前提を一覧化する。テンプレートに沿って三つの設計表を lesson.md に残し、各語を使う前に図で対象を指せるか確認する。
3. 全体像を身近な言葉で示す。知っている場面のどの関係を新しい対象へ渡すか、図と操作の対応、対応しない点、元の現象への戻り方を実際の表示で確認する。
4. 「説明と操作を一緒に設計する」の手順で、仕組みの図と操作を用意する。場面・見方・条件・時間を分け、配置と切り替え時の状態を設計表へ記す。
5. 式・単位・成立条件・資料を Markdown と画面で揃える。
6. 入力の強制・採点・説明課題がないか確認する。
7. 各場面で一つの関係が説明でき、入口の現象へ戻れるかを確認する。必要な図の案内と中間段階を残し、重複や演出だけの文を除く。
8. 開発テストでモデルの科学的な性質と設計表の構造を確かめ、操作UIを変えた場合は「実画面で確認すること」に沿ってブラウザを一周する。確認した画面幅と操作、残る未確認事項を報告する。

## 結像の教材で確認すること

像の説明は、物全体の光が一つの点へ集まるように書かず、物の一点と像の一点の対応を図で示す。
先端と根元など、同じ二点を保ったまま像の向きと大きさへつなぐ。
実際の光路と、出た後の向きを逆に延ばした幾何学の線は線種で分ける。
虚像が見えることと、スクリーンへ直接映せないことを区別し、目の別のレンズによる結像とも分ける。

焦点は平行な光で決まる目印として導入し、一般の物の像の位置と混同しない。
像の位置、スクリーンの位置、目の位置の役割を分け、一つの変更でほかの条件を勝手に追従させない。
焦点ちょうどや描画範囲外を通常の有限の像として見せず、式と図で境界の意味を示す。
縮尺や見る断面が変わる場合は、図の近くに明記する。

一回のレビューで表の完成を判定せず、次の観点で実装へ戻る。
まず前提・各点の対応・境界条件を資料と式で照合し、次に場面ごとの名前の導入と因果の中間段階を図で指す。
最後に実画面で条件と表示の同期、変わらない条件、狭い画面とキーボードを確認する。
修正した配置と状態を設計表へ戻し、レビューの指摘と修正、確認できた範囲を lesson.md に残す。
