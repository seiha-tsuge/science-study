# 設計と実験の追加

## 目的

世界の解像度を上げ、「なぜそうなるのか」を図と操作で理解することを目的に、1リポジトリ・1パッケージ・1アプリで育てる。
位置と速度、加速度、光の反射と屈折の3題を扱う。
文章と図の設計は各教材の lesson.md、計算は model.ts、表示はTSXに置く。
この文書は、その責務の分け方と教材の追加手順を示す。
依存関係は必要になったものだけを追加する。
Three.js、MDX、グラフライブラリ、バックエンド、認証、ノート保存・同期は現時点では使わない。
共通のUIはMantine（`@mantine/core`・`@mantine/hooks`）を使用する。
`main.tsx`で標準CSSとMantineProviderを読み込み、`app/theme.ts`で色・文字・角丸を設定する。
ナビゲーション、カード、ボタン、場面選択、スライダー、表、初期条件の開閉にはMantineを使う。
独自CSSは教材のレイアウト、SVG・canvas、数式と説明演出に限定し、フォームやボタンの基本スタイルを再定義しない。
条件の操作や時刻制御は既存のReact状態とフックが担い、Mantineへ科学モデルを持ち込まない。

## 責務

| 層 | 責務 | 持ち込まないもの |

| routes | URL とページの接続 | 科学の計算 |
| app | 学習マップ・分野・共通ナビゲーション | 実験モデル |
| LessonPage.tsx / meta.ts | 教材の組み立て・全体像・関係・概念への接続 | 描画ループ |
| lesson.md | 身近な感覚から概念への橋渡し、概念の導入、観察と説明の設計表、式、単位、成立条件、参考資料 | 個人の学習履歴 |
| model.ts | 条件と時刻から観察量を計算 | React・p5・DOM・ピクセル |
| Simulation.tsx | 条件と比較対象を選ぶ | 物理法則の実装 |
| motion/ExplanationAnimation.tsx | SVGの模式図・グラフとGSAPの説明演出 | 物理法則の実装 |
| motion/explanation-timeline.ts | 説明の場面・説明の時間から物理時刻への対応 | ピクセル・描画ループ |
| shared/useExperimentClock.ts | 再生・停止・時刻の指定 | 位置や速度の計算 |
| shared/sketch.ts | p5 instance mode による描画・座標変換 | 物理状態の更新 |
| shared/Graph.tsx | 解析式のグラフを SVG で描画 | 実測データと呼ぶこと |
| optics/reflection-refraction/model.ts | スネルの法則・反射方向・臨界角・物質中の速さ | DOM・ピクセル・物理時刻の演出 |
| optics/reflection-refraction/RayDiagram.tsx | 単位方向ベクトルからSVG光線図への変換 | 光の強さの計算・モデルの更新 |

共通部分は実際に2題で使うものだけに限定している。
`components/Lesson.tsx` は全3題の「全体像 → 仕組み → 条件変更 → 任意の式と前提」を共有する。
`LessonContent` に身近な入口（startingPoint）・全体像・概念の関係・接続を必須にし、仕組みの図を必須の `mechanism` として受け取る。
教材の構成テストは全3題の図と操作が最初から表示され、回答の入力で制限されないことを確認する。
力学の既存2題は既定の分野・参考資料を使用する。
`Lesson` の任意の `overviewVisual` は、全体像の本文に対応する図を添えるための表示枠である。
光学では既存の `StrawDiagram` を再利用し、`className` と教材内の `optics-lesson.css` でそのページの配置を調整する。操作部品の色・形状はMantineの標準と共通テーマに任せ、部品の外観をCSSで上書きしない。
`RefractionJourney` は四場面をMantineの `Tabs` で選ぶ。
同じ場面の再選択では条件を保ち、別の場面への移動では説明時計を停止・初期化する。
図と、`SegmentedControl`・`Switch` による操作と説明を二列に配置し、狭い画面では同じ場面の中で縦に並べる。
操作の役割をラベルで示し、時間の選択・再生・停止を図の近くに置く。
人の列のA・Bの状態と速さは `observeWalkingRow` の結果を表示し、説明も現在の状態に対応させる。
光線図の三つの場面ボタンは角度と物質の既存の状態を一緒に切り替える。角度は `Slider` と `NumberInput` が同じ状態を共有し、数値入力からモデルへ渡す値は0〜80°の有限値に限る。
出発側と進む先の選択を並べ、速さの表と図の注記は条件操作の後のMantine `Accordion` で任意に開く。
`Trajectory.observe(t)` は現在の2題を描画するための小さな契約で、全分野向けのモデル基盤ではない。
式の可視化・数値シミュレーション・実測データの可視化は、それぞれ教材に明記する。

## 時間と描画

モデルは解析式を評価する。
数値積分の時間刻みはない。
再生には requestAnimationFrame のタイムスタンプの差を使い、フレーム数に依存させない。
描画は p5 の noLoop / redraw で現在の計算値を表示する。
0〜10秒の範囲で実行し、10秒で停止する。
非表示のタブでは一時停止する。
時刻を直接指定したときも一時停止する。
条件を変えると実行部を再生成し、時刻0・停止状態に戻す。

ResizeObserver は canvas の表示幅だけを更新する。
モデルに画面の大きさを渡さない。
p5 は動的 import し、未マウント後の初期化を防ぎ、離脱時に remove と observer の解除を行う。
React StrictMode の再マウントでも描画インスタンスを残さない。
グラフの軸は表示中の条件の0〜10秒の値から決定するため、条件を変えると縮尺も変わる。
比較表示中の2本のグラフは同じ縮尺を使う。

### 等速運動の説明アニメーション

`motion/ExplanationAnimation.tsx` は仕組みの節に最初から表示する。
React・SVG・GSAPと`@gsap/react`を使い、説明の22秒とモデルの物理時刻を分ける。
物理時刻は説明の2〜6秒に0〜4秒まで等倍で進み、それ以外の場面では停止する。
位置は既存の`observeMotion`で計算し、物体の座標に演出用のイージングを適用しない。
固定条件は x₀ = 0 m、v = 5 m/s。
印とグラフは過去の0〜4秒の位置を振り返る。
SVGへの座標変換は表示側に置き、フレーム数から物理時刻を計算しない。
グラフの線が現れる演出は、物体の運動や追加の物理時間を表すものではない。

GSAPのタイムラインは停止状態で作り、再生・一時停止・初期化・任意の秒への移動を扱う。
場面の選択ではその場面の終了時刻へ移動して停止する。
22秒で停止し、再生すると最初から始める。
非表示のタブでは停止する。
ページを離れると`useGSAP`のcontextが演出を破棄し、
visibilitychangeとメディアクエリのイベントリスナーも解除する。
動きを減らす設定では再生を無効にし、最終場面から静止画で各場面を確認できる。
共通の演出基盤や動画書き出しは追加していない。

`explanation-timeline.test.ts`では初期位置、運動中の一定速度、説明中の物理時刻の停止、
巻き戻し時の再現性を既存モデルと照合する。
現実への適用範囲は既存の等速運動の前提に限る。

描画の矢印は速度の向きだけを示す。
長さは速さに対応しない。
グラフは全10秒の式を先に表示し、縦のカーソルと点で現在時刻を示す。
canvas の代わりに読み取れる現在値の表と SVG の説明を用意する。

## 学習の流れと記録

### 光の反射と屈折

`/optics` を分野の入口、`/optics/reflection-refraction` を教材とする。
`model.ts` は角度をrad、速さをm/s、方向を単位ベクトルで計算し、画面の幅を受け取らない。
`Simulation.tsx` は角度・物質の選択と初期化を担当し、物理法則は実装しない。
`RayDiagram.tsx` はResizeObserverで幅を読み、モデルの方向をピクセルに変換する。
非表示の再生ループはなく、条件変更・初期化は静止した解析式の図で行う。
離脱時にobserverを解除する。
p5、GSAP、共通の光学描画基盤や依存関係は追加しない。
同じ屈折率では反射光を描かず、全反射では屈折光を描かない。
臨界角は境界に沿う限界として示す。
線の長さや太さを光の速さ・強さには対応させず、数値と成立条件を別に示す。
モデルのテストは既知の解・対称性・光路の可逆性・臨界角の境界を確認する。
実測で現実の水面やガラスへの適合を確かめたものではない。

### 仕組みをたどる図

加速度の `AccumulationDiagram.tsx` は速度と時間の面積を長方形と三角形に分ける。
`model.ts` の `accelerationDisplacementParts` がそれぞれの符号付き変位をmで返す。
図では初期位置0 m・初速度2 m/s、時間0〜8 s・加速度0〜2 m/s²に絞り、固定の軸で比較する。
初めは二つを重ねた全体を示し、ボタンで寄与を一つずつ強調する。
スライダーは積み重ねる区間を指定する。
運動の再生条件とは独立し、自動再生や時間ループを持たない。

光学の `RefractionJourney.tsx` は「ストロー → 人の列 → 波の目印と光の向き → ストロー」の四場面を担う。
入口と着地点には同じ `StrawDiagram.tsx` を使い、形・光路・光の延長を段階的に重ねる。
`model.ts` の `observeWalkingRow` は固定の向きに歩く人の模式図、`observeStrawPoint` はスネルの法則から一点の近似像を計算する。
たとえは到着順・進む距離の差・列の傾きの対応に限り、光の向きが波面に90°となる性質とは分ける。
水の山の列と光の目印は、A側・B側の配置を保って切り替える。
光の境界図は `boundaryFrontPoint` を使い、矢印を後から重ねる。
主な流れは最初から開き、電場・干渉・位相の `WavePrimer` とホイヘンスの作図は任意の詳細へ置く。
説明の静止場面、時刻指定、再生・停止は既存の `useWavePresentation` を使う。
人の図は説明8秒を歩行1.5秒に変換し、光の図の物理時刻とは区別する。

任意の詳細の `WavePrimer.tsx` は、ひもの波・光の電場・干渉の手がかり・位相・波面・空気と水の境界を六場面で導入する。
物理量は `model.ts` の正弦波、場、合成、位相、境界の波面の関数から計算する。
SVGは表示座標への変換と、対象を示すラベルを担う。
図の前には見る対象、図の後には名前とその場面で分かる関係を置く。
`useWavePresentation.ts` は説明の時間を0〜8秒で管理し、タイムスタンプの差で進める。
自動再生しない。
通常の波の場面は説明2秒を1周期に変換し、光の物理時刻と区別する。
水面の場面は別の尺度で8秒を約4.00 nsに変換し、一つの波面の到達を描く。
反射や場の強さはこの図に含めない。
六場面は標準Tabsで選び、比較・見方はSegmentedControl、独立した磁場と法線の表示はSwitchにする。
広い画面は図と説明の横に条件・静止時刻・再生と時間指定を置き、狭い画面は同じ場面内で縦に読む。
別の場面と比較条件の変更で0秒・停止へ戻し、同じタブの再選択と図の見方の変更では保持する。
`LessonPage` が詳細の開閉状態を渡し、`useWavePresentation(active)` が閉じた領域の再生を停止する。条件と時刻は保持し、再開は手動。
非表示のタブで停止し、離脱時はRAFとイベントリスナーを解除する。
動きを減らす設定では再生を無効にし、スライダーで静止画を見られる。
位相の円は説明の対応図、奥行きのある波面はSVGの投影図。
3Dライブラリは追加しない。

光学の `WavefrontDiagram.tsx` は任意で開く詳細とし、ホイヘンスの作図を三つの場面に分ける。
`model.ts` の `constructRefractionWavefront` が境界への到達時刻差、二次波の半径、接点をSI単位で計算する。
図は空気→水・ガラス・空気（同じ速さの比較）、0°・30°・45°・60°を扱う。
到着段階から始め、Tabsで距離・接線へ移り、同じ基準長のもとで条件を保持して比較する。
条件と二つの進行距離・経過時間を図の横に置き、作図の式と範囲は内部のAccordionへ分ける。
0°の到着直後は半径0、同じ速さでは波面の向きが変わらない条件として説明する。
半円は二次波の断面で、粒子の軌道ではない。
反射光・干渉・全反射の境界付近の波はこの図に含めない。
作図の段階を切り替えるだけで物理時刻は再生せず、光線図の条件とも独立する。
テストは同じ時間の進行距離、光線と波面の直交、接線の条件、縮尺に対する方向の不変性を確認する。

### 共通の探索と記録

全体像は身近な入口と既知の言葉から示す。
未説明の用語を土台にせず、図で見た対象に名前を付けてから関係を示し、仕組みの図は最初から見える。
図の場面、実験の条件、再生、任意の式と前提へ、好きな順序で移れる。
予想・理解度チェック・採点・説明課題・完了チェックはなく、図や操作を入力でロックしない。
認知への配慮と追加時の確認は [教材の設計契約](content-design.md) にまとめる。
[文章と図の規範](writing-guidelines.md)は科学的な正確さと必要な足場を優先し、観察と説明の緩急を本文と図に適用する。
[教材設計テンプレート](templates/lesson.md)の三つの設計表を各 `lesson.md` に残し、実装と同時に更新する。
新規・改善は[説明と操作を一緒に設計する手順](content-design.md#説明と操作を一緒に設計する)で進める。
「観察と説明の流れ」には、各場面の図・説明・操作の配置と、切り替え時に保持・停止・初期化する状態も記す。
役割に応じて標準部品を選び、モデルの状態を表示部品へ重複して持たせない。
設計表は制作者の記録であり、表示用のデータモデルや学習者への課題にはしない。
`tests/lesson-design.test.ts` は全教材の `LessonPage.tsx` を自動で探索し、Markdownと設計表の存在、列、記入を確認する。テンプレートの列も同じ検査で照合し、配置と切り替え時の状態の書き忘れを検出する。
Markdownを読むNode.jsの検査は `tests/` に置き、`tsconfig.node.json` で型検査する。
ブラウザ用のアプリへNode.jsの型やファイル読み取りを持ち込まない。
これは追加の依存関係なしで `pnpm test` に含まれ、新規教材の検査対象を手で登録する必要はない。
説明の意味や科学的な妥当性は構造検査で判定せず、本文、図、モデル、資料の対応をレビューする。

教材のMarkdownと表示用TSXの式・前提・仕組みの説明は同時に更新する。
個人メモは任意の `notes/journal/`、概念の関連は `notes/concepts/` に置く。
記録を要求せず、本人の理解の変化や学習履歴を捏造しない。
保存・同期の基盤も増やさない。

## 教材を追加する手順

1. `docs/content-design.md` と `docs/writing-guidelines.md` を読み、概念の地図で中心の「なぜ」と扱う深さを決める。
2. `docs/templates/lesson.md` から各教材の `lesson.md` を作り、問いを因果の関係へ分ける。橋渡し・概念・場面の設計表へ図の対象と操作、配置、切り替え時の状態を具体的に記す。
3. `src/experiments/<分野>/<テーマ>/` に meta、model、model.test、仕組みの図、Simulation、LessonPage を置く。設計表に沿って説明と図を組み立てる。
4. モデルは SI 単位で扱い、既知の解・不変量・対称性など科学的な期待値をテストする。
5. routes にページをつなぎ、学習マップと分野ページに概念のつながりを示す。
6. 本文と図をレビューし、身近な場面から渡す関係とその限界、前提、比較対象、問いの説明、現象への接続を確認する。設計表と実装の対応をそろえる。
7. lint、型検査、テスト、ビルドを実行し、設計表の構造検査と生成ルートも確認する。
8. 設計契約の「実画面で確認すること」に沿ってブラウザを一周する。広い画面と390pxを目安にした狭い画面で、条件の境界や変化しない場合、入力と図の同期、キーボード、再生・停止・初期化・詳細・離脱を確認し、幅・操作・未確認事項を報告する。

数値積分を導入するときは、解析解との比較、刻みに対する収束、保存量の誤差を検証する。
確率的なモデルではシードと複数回の試行を扱う。
実測では測定方法・単位・不確かさを残す。
テストで式の実装を確認することと、その式の現実への適用範囲を確認することは区別する。

## 公開

Viteのビルド結果 `dist/` をCloudflare Workersの静的アセットとして手動で公開する。
`wrangler.jsonc` は配信先の名前、互換性の日付、配信ディレクトリ、SPAフォールバックを定義する。
`pnpm run deploy` は `pnpm build` が成功した場合だけ `wrangler deploy` を実行する。
教材URLへの直接アクセスは `single-page-application` 設定で `index.html` に接続し、TanStack Routerがページを選ぶ。
Workerのサーバー処理やGitHub連携による自動公開は追加しない。
公開範囲は `dist/` に限り、個人メモやソースのMarkdownは配信しない。
Wranglerのローカル状態 `.wrangler/` はGitの管理対象から除外する。
